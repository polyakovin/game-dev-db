# Security policy

Game Dev DB is a public static site. Build dependencies and deployment workflows can still affect the integrity of published content.

## Reporting a vulnerability

For a suspected vulnerability, check the repository's Security tab for private vulnerability reporting. If it is available, use it. Otherwise, contact a maintainer through a listed private channel. If neither exists, open a minimal issue requesting a private security contact without including exploit details, secrets, or personal data.

A useful private report describes the affected file or URL, the impact, a minimal reproduction, and any proposed fix. Do not test against other users or obtain data you are not authorized to access. There is no guaranteed response time or bug bounty.

Ordinary broken links, inaccurate lessons, and visual bugs belong in public issues.

## Scope

Maintenance focuses on the current default branch and the current GitHub Pages deployment. Old snapshots and forks do not receive separate security maintenance. Never put tokens, private keys, `.env` files, or service-account credentials in an issue, pull request, or lesson.

## По-русски

Об уязвимости сообщайте приватно через Security на GitHub, если эта функция доступна, либо по опубликованному контакту мейнтейнера. Если личного канала нет, откройте issue с просьбой предоставить его, без деталей эксплуатации и секретов. Для обычных ошибок сайта и материалов подходят публичные issues.
