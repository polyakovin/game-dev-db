# Proposal

## Why

Agents can already retrieve individual knowledge records, but most mechanics, exercises and lenses only have catalog fragments as their HTML address. Search discovery needs focused static pages, accurate metadata and a measurable publishing and webmaster handoff.

## What Changes

- Publish bilingual standalone pages for active mechanics, exercises and lenses from existing common records, retaining all old catalog routes and anchors.
- Give common records precise canonical page URLs; retain existing type-specific v1 exports and catalog placements.
- Link individual pages from catalogs, search, agent indexes and a dated, language-aware sitemap.
- Expose per-record Markdown/JSON discovery and accurate structured metadata; provide reusable repository instructions for agents.
- Deliver a reproducible discovery audit and an RU/EN question set, plus exact webmaster registration and root robots instructions. Complete accessible account setup and deployment; report authentication requirements explicitly.

## Capabilities

### New Capabilities

- `search-discovery`: focused indexable pages, crawler entry points, metadata and verifiable discovery operations.

### Modified Capabilities

None. New requirements extend the existing common record and static portal contracts; existing URLs and legacy API shapes remain valid.

## Impact

Task-owned paths: new standalone knowledge route, knowledge builder/types and links, shared layout, lesson metadata, sitemap and llms generators, agent guide and manifest, discovery audit and evaluation files, tests, documentation, README and this OpenSpec change. No new service, runtime secrets, paid hosting or automated outreach. Pre-existing .gitignore, .project-control-panel and .lavish changes remain outside this task.
