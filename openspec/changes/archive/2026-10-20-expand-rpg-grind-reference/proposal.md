# Proposal

## Why

The current RPG grind reference contains thirty introductory examples but omits major economy, exploration, companion, automation and reward-control systems. The user requested a comprehensive design reference on the existing site.

## What Changes

- Expand `rpg-grind` into a broad bilingual reference with at least 110 distinct families and 330 concrete variants across four explicit layers: activities, progression goals, reward rules and pacing/cost constraints.
- Cover combat, repeatable challenges, gathering and production, exploration, trade, delegation, character and gear growth, companions, access, world/social progress, collections and metaprogression.
- Preserve all existing catalog, section, family, branch and variant identities, add a coverage matrix and combination recipes, and distinguish design illustrations from primary-source game observations.
- Reuse existing search, filters, static reading and v1 exports; test the expanded source and legacy links in both languages.

## Capabilities

### New Capabilities

None.

### Modified Capabilities

- `mechanics-reference`: broaden RPG grind coverage while retaining all published identities and export compatibility.

## Impact

RPG catalog data, its documentation, a focused browser/coverage test and the existing mechanics specification. No dependency, UI redesign, runtime service or API schema change. Work in a managed worktree to preserve unrelated ongoing changes.
