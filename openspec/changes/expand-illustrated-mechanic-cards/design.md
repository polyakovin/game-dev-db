## Scope and order

Use active canonical `mechanic` records from the knowledge builder, excluding
the 64 archived compatibility records. Shared placements already use one
canonical identity. Keep one editorial production list and validate it against
that inventory. Start with fundamental movement, health, combat, interaction,
inventory, dialogue, resources and progression. Continue through specialized
systems and hardware directions. Do not claim a market-frequency measurement.

## Content and images

Keep authored bilingual cards in the existing mechanic preview source. Add a
concise display title without replacing the stable record title. A card needs
an inspected screenshot from a known game/application, its original source and
rights, and labels pointing to the relevant visible elements. Use official
publisher/developer materials where available. Crop via metadata; preserve the
source image. Reuse an image only when it actually demonstrates the mechanic.
Keep one or two short tips and a bounded set of explicit example links; full
reference sources remain in the record and exports.

## Incremental publication

A priority entry is not a completed illustrated card. Only complete, validated
preview entries switch to the compact layout. Existing reference pages remain
available until their authored card is ready. Publish verified batches without
claiming the full rollout complete. Keep this change active until coverage is
complete; maintain an actionable report of remaining canonical IDs.

## Verification

Validate localization, stable identity, source URLs, local image files and
dimensions, crop bounds, marker membership and short-content limits. Exercise
every new card in RU/EN at tiny portrait, short landscape, desktop and fullscreen
sizes. Retain keyboard/touch tooltips, no-JS titles, both themes, category links,
search and full JSON/Markdown parity. Run canonical checks and browser tests,
then verify each published batch on GitHub Pages.
